# 02. 파이프라인

> R3에서 확정했고, 1차 리뷰 뒤에 고쳤어요. 작업 문장 번호는 [story-work.md](../docs/story-work.md)를 따라요.

## 단계

| 단계 | 이름 | 묶는 문장 | 입력 | 출력 | 화면별 병렬 |
|---|---|---|---|---|---|
| S1 | research | 1 레퍼런스 수집 · 2 분석·반영 포인트 | 대상 화면 목록, prd.md | 레퍼런스 목록(uibowl 링크) + 반영 포인트 | — |
| S2 | spec | 3 화면 설계 문서 | S1 출력, prd.md, story-service.md | 화면별 설계 문서 + 화면 문구 | ✅ |
| S3 | keyscreen | 4 Figma 키스크린 · 5 시안 확정 | S2 출력, design.md | Figma 키스크린 프레임(입력 화면 N개) + 승인 기록 | — (화면 간 컨셉 통일) |
| S4 | build | 6 토큰·컴포넌트·화면 디자인 | 승인된 S3, design.md | Figma 완성 화면 + 프레임 ID | ✅ |
| E | extract | — | run 페이지(`run-<id>`) | 판정 증거(페이지의 최상위 프레임 **전부**를 Figma에서 직접 추출) | — |
| S5 | review | 7 design.md 위반 검토 | 판정 증거, design.md | 판정 결과(위반 목록, 위반 건수) | — |

- **E(extract)**는 G3 앞과 S5 앞에서 돌아요. 판정 증거는 작업 에이전트가 아니라 `extractor`가 Figma에서 직접 뽑아요.
- **화면별 병렬**: S2와 S4는 화면마다 에이전트를 하나씩 동시에 띄워요. 각 에이전트는 자기 화면만 다뤄요.

## 되돌아가는 지점

| 실패 | 돌아갈 단계 | 넘기는 입력 | 다시 하는 범위 |
|---|---|---|---|
| G1 실패 | S1 | 위반 목록 | 전체 |
| G2 실패 | S2 | 위반 목록 | **위반이 있는 화면만** |
| G3 승인 거절 | S2 | 거절 사유 | 전체 |
| G5 실패 | S4 | 위반 목록(노드 ID 포함) | **위반이 있는 화면의 해당 노드만** |

- 재시도는 **돌아간 단계**의 `retries`에 세요. 예를 들어 승인을 거절하면 `retries.S2`가 1 올라가요.
- 같은 단계는 **최대 2회**까지 다시 해요. 3회째 실패하면 멈추고 실행자에게 물어요.

## 키스크린 개수

- 키스크린 개수는 **입력한 화면 수 N**과 같아요(1~3개).
